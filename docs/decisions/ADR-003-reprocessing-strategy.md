# ADR-003: Reprocessing Strategy

## Status

Accepted

---

## Date

2026-07-08

---

## Context

As the platform evolves, parser improvements, defect fixes, and business requirements may require previously processed source documents to be processed again.

Updating existing Raw records would compromise auditability, break reproducibility, and destroy historical processing information.

A formal reprocessing strategy is required to preserve historical integrity while allowing the platform to evolve.

---

# Decision

The platform adopts an append-only reprocessing strategy.

Reprocessing never updates existing Raw records.

Instead, each reprocessing event creates a new pipeline execution that produces a new Raw dataset.

Historical executions and their associated datasets remain available for auditing, comparison, and reproducibility.

---

# Reprocessing Lifecycle

```
Source Document

        │

        ▼

Pipeline Execution #1

        │

        ▼

Raw Dataset A

        │

Parser Improvement

        │

        ▼

Pipeline Execution #2

        │

        ▼

Raw Dataset B
```

Both datasets remain permanently stored.

No historical records are modified.

---

# Operational Principles

The platform shall:

* Preserve every successful pipeline execution.
* Preserve every Raw dataset generated by those executions.
* Allow historical executions to be inspected and compared.
* Allow downstream processing to select the pipeline execution designated for transformation.
* Never overwrite historical Raw data.

---

# Rationale

An append-only strategy provides several advantages.

* Complete audit history.
* Reliable debugging.
* Safe parser evolution.
* Historical comparison between processing versions.
* Deterministic reprocessing.
* Improved operational transparency.

The additional storage required is negligible compared to the value of maintaining historical processing records.

---

# Consequences

## Positive

* Historical processing is preserved.
* Parser defects can be corrected without data loss.
* Reprocessing becomes repeatable and auditable.
* Complete lineage is maintained.

## Trade-offs

* Multiple processing executions may exist for the same source document.
* Metadata management becomes responsible for determining which execution downstream processing should use.
* Additional storage is required for historical datasets.
